Exam-Oriented Questions and Answers

Q1. Explain the complete architecture of a Todo Application with neat diagrams.

A Todo Application is a web-based application used to manage daily activities such as adding, updating, deleting, and viewing tasks. The complete architecture of a Todo application is divided into Frontend, Backend, Database, and Authentication layers.

Frontend Layer

The frontend is the user interface of the application. It is developed using frameworks such as React, Angular, or Vue. It includes components like Todo Input, Todo List, and Filter components.

Backend Layer

The backend is developed using Node.js and Express.js. It provides REST APIs to handle client requests and perform business logic.

Database Layer

MongoDB is used to store user data and todo information. Mongoose is used for schema definition and validation.

Authentication Layer

Authentication is implemented using bcrypt for password hashing and express-session for session management.

User
↓
Browser (Frontend)
↓ HTTP Requests
Server (Express)
↓
MongoDB Database

Conclusion: The layered architecture ensures scalability, security, and maintainability of the Todo application.

Q2. Describe the frontend architecture of a Todo Application.

The frontend architecture of a Todo application follows a component-based approach. Each component is responsible for a specific function.

  • Input Component: Accepts user input
  • List Component: Displays all tasks
  • Item Component: Represents a single todo
  • Filter Component: Filters tasks

State management ensures that whenever data changes, the UI automatically updates.

User Action → State Change → UI Re-render

Conclusion: Component-based design improves code reusability and clarity.

Q3. Explain LocalStorage and MongoDB. Compare them.

LocalStorage

LocalStorage is a client-side storage mechanism used to store small amounts of data in the browser. It is simple but not secure.

MongoDB

MongoDB is a NoSQL database that stores data in JSON-like documents. It is secure, scalable, and suitable for multi-user applications.

Feature LocalStorage MongoDB
Storage Location Browser Server
Security Low High
Scalability No Yes
Multi-user Support No Yes

Conclusion: MongoDB is preferred for real-world web applications.

Q4. Explain backend architecture using Node.js and Express.

The backend of a Todo application is built using Node.js and Express.js. It manages APIs, authentication, and database communication.

  • Routes: Handle URL requests
  • Controllers: Contain business logic
  • Models: Define database structure
  • Middleware: Process requests and responses

Conclusion: Express provides a scalable and organized backend structure.

Q5. Explain user authentication using bcrypt, express-session, and MongoDB.

User authentication verifies the identity of a user before granting access.

Registration

  • User submits details
  • Password is hashed using bcrypt
  • Hashed password is stored in MongoDB

Login

  • User enters credentials
  • Password is verified
  • Session is created using express-session
  • Session ID is stored in a cookie

Conclusion: This approach ensures secure authentication.

Q7. Explain cookies and cookie-parser.

Cookies are small pieces of data stored in the browser. cookie-parser is middleware that reads cookies from request headers.

Conclusion: Cookies play a key role in session management.

Short Notes

  • HTTP Statelessness: HTTP does not remember previous requests.
  • REST API: Uses GET, POST, PUT, DELETE methods.
  • Middleware: Executes between request and response.
  • bcrypt: Used for secure password hashing.
